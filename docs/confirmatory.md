# 确认性实验分析

描述性浏览回答「现在各组均值是多少」，不构成上线结论。确认性分析回答评审会的三个问题：效应范围有多大、多个方案按联合规则能否上线、当前资料是否已经足以判断。两者共用同一份资料与同一套成熟度口径，但只有确认性分析消耗检验额度。

## 一、先保存计划，再打开结果

计划（design）在保存时冻结以下内容，之后不随资料定义或页面筛选改变：

- 对照方案与待评方案族，人群范围；
- 指标清单，以及每个指标的方向、业务门槛 `margin`、成熟天数与业务角色（收益或保护）；
- 总体单侧 α、计划最多查看次数 `K`、单组观测下限、可接受的缺失率上限；
- 判定规则文本、当时的资料指纹与业务时点。

结果一旦可看，后改的指标或人群不能再沿用原计划的确认性结论：

- 同一资料已有未打开的计划时，保存新计划会替换它（`superseded_by`），原计划不能再查看，避免同一份资料领到两份额度；
- 同一资料的计划已经打开过结果后，再保存计划必须标记为探索（`preregistered=false`），探索计划没有确认性额度、不产生判定；
- 已用尽额度的计划不能续借；继续查阅只能走描述性浏览或另存探索。

计划本身要到查看时态才做计算，因此「计划里写的是时点 60」不会在读结果前泄露任何效应。

## 二、错误率依据

页面与接口暴露完整的分配表（`GET /api/designs/{id}/schedule`），可逐项复核。

1. **重复查看**：计划最多查看 `K` 次，第 `k` 次使用 O'Brien–Fleming 单侧消耗
   `S(t) = 1 − Φ(Φ⁻¹(1−α)/√t)`，`t = k/K`；第 `k` 次的增量为 `α_inc(k) = S(k/K) − S((k−1)/K)`。
   前几次查看阈值很严，末次用满 α；`Σ α_inc(k) = α` 由结果中的 `checks.equals_alpha` 断言。
2. **多重假设**：每次查看要同时判定 `M = 待评方案数 × 指标数` 个比较，每个比较用单侧水平
   `α_inc(k)/M`，临界值 `z = Φ⁻¹(1 − α_inc(k)/M)`。
3. **共用对照**：所有待评方案都与同一对照比较，比较之间正相关。Bonferroni 在正相关下偏保守，
   但仍保证族错误率，因此不需要额外假设。
4. **合并保证**：跨全部 `K` 次查看与 `M` 个比较，第一类错误不超过 `α`（并集界）。未调整的 `p` 值
   只作参考，判定以调整后的区间与阈值是否越过业务门槛为准。

`error_budget` 会随每次查看一起冻结保存，包含当次的 `alpha_per_comparison`、`critical_value`、
`cumulative_alpha` 以及整张 `schedule`，因此事后可以核对当时的阈值，而不是套用现在的参数。

## 三、效应范围与缺失

- 收益指标（`direction=higher`）给出单侧下界 `效应 − z·SE`；保护指标（`direction=lower`）给出单侧上界
  `效应 + z·SE`。`SE` 由两组观测方差与各自观测数得到，对照与方案共用同一份对照观测。
- 方向统一后计算 `oriented_effect = sign·(效应 − margin)`，`z = oriented_effect/SE`。
- 成熟但无结果、结果为空值、尚未到可见时点的用户分别记为 `missing` / `null` / `pending`，
  一律不计入均值，也不补零。保护指标未成熟时该比较标记为 `blocked`，不产生效应或判定，
  方案状态为「尚不能判断」。
- 成熟样本的缺失率超过计划上限，或观测数低于计划下限时，同样只能等待，不能按零处理。

## 四、判定规则

1. 每个比较给出三态之一：`pass`（调整后单侧区间越过业务门槛）、`fail`（调整后区间整体落在门槛不利侧）、
   `unconfirmed`（区间仍覆盖门槛，证据不足以判断）。零方差或成熟度不足不判为失败，只标为未判定。
2. 一个方案可上线，当且仅当它所有收益与保护比较都 `pass`。
3. 若仍有方案未判定，本次决策为 `wait`；查看额度用尽后仍未判定则为 `inconclusive`（证据不足）。
4. 全部方案都可判定后：恰有一个通过为 `recommend`；多个通过为 `ambiguous`（计划未预注册方案间比较）；
   都未通过为 `none`。
5. `decision.fully_accrued` 与 `accrual_end` 说明当前人群与指标是否已全部成熟，用于区分
   「再等资料」与「再等也不会有更多观测」。

## 五、从页面追回计划与数据范围

每个打开的结果都保存为一条不可变查看记录（`looks`），页面展示并保留：

- 查看结果编号 `look_id`、计划编号 `design_id`、查看次序、打开时间；
- 当时的资料指纹 `digest`、业务时点与人群；
- 冻结的计划快照、错误率分配、效应、成熟度与判定。

`GET /api/designs/{id}` 返回计划的全部查看记录与剩余额度，`GET /api/designs/{id}/looks/{k}` 返回
第 `k` 次查看的完整冻结结果；两者都不重算。资料被替换后旧查看记录仍然原样可读。
